# VoiceEye 발표자료·MVP 교차검증 기록

검증일: 2026-09-16

## 발표용 MVP

- 첫 화면을 80초 자동 회의 시연으로 변경했다.
- 흐름은 회의 시작 → 안건 제시 → 동시 발언 → 확인 구간 표시 → 비공개 문장 작성 → 한국어 음성 발언 → 결정 확인 순서다.
- 화면에 `시연용 대본 · 실제 마이크 성능 측정이 아님`을 계속 표시한다.
- 실제 STT·TTS 기능 점검 화면은 `/lab`에 남겼다.
- 발표장에서는 `VoiceEye_발표용_MVP_USB.zip`을 풀고 `index.html`을 Chrome 또는 Edge로 열면 된다. 인터넷, Node.js, API 키가 필요하지 않다.
- 한국어 음성이 없는 PC에서는 TTS만 나오지 않고 화면 시연은 계속된다.

## 코드 검증

- `npm run test:mvp`: 18개 통과
  - STT 회귀시험 7개
  - TTS 회귀시험 9개
  - 발표 시나리오·휴대용 HTML 시험 2개
- `npm run typecheck`: 통과
- `npm run build`: 통과
- 실제 마이크 인식률, 지연, TTS 자연스러움은 아직 실측하지 않았다.
- 좌석, 동시 발언, 자막 공백 표시는 발표용 대본 데이터다. 실시간 화자 판정 결과가 아니다.

## PPT 재검토

- 19쪽 전체 발표자 노트를 각 슬라이드 대본으로 교체했다. 같은 도입문이 반복되던 문제를 없앴다.
- 9쪽 STT 상태를 `시험 통과`로 수정하고 실제 마이크 성능은 미측정이라고 명시했다.
- 10쪽 재시작·중복 결과 차단, 무음 자동 재시작 중단, TTS 재생 중 STT 중지를 현재 구현으로 반영했다.
- 12쪽 예산 그래프를 장비 15, 참여자 33, 외부 주석 16, 자문 20, 교통·소모품 9만원으로 다시 만들었다.
- 19쪽 시연 설명을 80초 자동 회의 시나리오에 맞췄다.
- 제목의 긴 대시 표현을 가운데점으로 바꿨다.
- 19개 슬라이드, 19개 서로 다른 발표자 노트, 발표 대본 표식을 확인했다.
- 목표값은 실측값으로 표현하지 않았다.

## 예상질문 답변지 재검토

- `왜 시작했나`의 빈칸과 작성 지시문을 없앴다. 확인되지 않은 개인 경험을 만들지 않았다.
- 이미 해결한 재시작·중복 자막 문제를 앞으로 고칠 일처럼 쓴 답변을 수정했다.
- 30일 삭제는 현재 구현 기능이 아니라 본선 운영 기준이라고 명시했다.
- CER 15%를 달성값이 아닌 초기 목표로 설명했다.
- 현재 가능한 기능, 발표용 대본, 미측정 항목을 나눠 답하도록 정리했다.
- `faster-whisper`의 MIT 라이선스 표기는 공식 공개 저장소 기준으로 확인했다: https://github.com/SYSTRAN/faster-whisper

## 발표 전 현장 점검

1. USB ZIP을 풀고 `index.html`을 Chrome 또는 Edge로 연다.
2. 화면 배율을 100%로 두고 전체화면으로 전환한다.
3. `회의 시연 시작`을 누른 뒤 80초 흐름과 한국어 음성을 확인한다.
4. 음성이 없으면 음소거 상태와 Windows 한국어 음성 설치 여부를 확인한다. 화면 시연은 계속 사용할 수 있다.
5. PPT와 HTML을 각각 한 번 열어 둔 뒤 발표를 시작한다.

## 남은 한계

- 발표용 HTML은 안정적인 설명을 위한 대본 시연이다.
- 실제 회의 성능을 주장하려면 발표장과 별도의 실제 마이크·소음 조건 시험이 필요하다.
- 브라우저 STT의 처리 위치는 브라우저 정책과 기기 지원에 따라 달라질 수 있다.
