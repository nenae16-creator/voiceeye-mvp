# 모두의 AI 실험실 제출 PPT 10분 발표 대본

## 1쪽 — 표지 (0:00~0:20)

안녕하세요. 충청권에서 보이스아이를 제안한 이종현입니다. 보이스아이는 청각장애인이 소규모 대면회의에서 대화를 읽고, 직접 입력한 문장을 음성으로 전달하도록 돕는 회의 접근성 서비스입니다.

## 2쪽 — 서비스 개요 (0:20~0:50)

보이스아이의 핵심은 회의가 진행되는 순간의 참여입니다. 실시간 자막으로 대화를 읽고, 놓친 구간은 다시 확인합니다. 사용자가 문장을 작성하면 먼저 화면에서 확인한 뒤 전송하고, 기기에 설치된 한국어 음성으로 회의 참석자에게 전달합니다. 발언자 정보는 이름 대신 익명 좌석으로 표시하는 방향을 검토하고 있습니다.

## 3쪽 — 팀 구성과 역할 (0:50~1:05)

저는 서비스 기획과 React 개발, 화면 디자인을 맡았습니다. 본선에서는 데이터 수집과 시험, 결과 정리까지 직접 진행하고, 음성 처리 전문가의 자문과 청각장애인 참여자 평가를 연결할 계획입니다.

## 4쪽 — 현황과 문제점 (1:05~1:40)

소규모 대면회의에서는 말을 놓쳐도 대화를 끊고 다시 물어보기 어렵습니다. 여러 사람이 겹쳐 말하면 자막을 보더라도 누가 어떤 말을 했는지 혼동하기 쉽습니다. 또 의견을 키보드로 입력하는 동안 회의는 계속 진행됩니다. 보이스아이는 문자 읽기와 키보드 입력을 선호하는 청각장애인이 이 과정에서 겪는 불편을 줄이기 위해 시작했습니다.

## 5쪽 — 제안 필요성 (1:40~2:10)

수어 통역과 문자통역은 의사소통을 직접 지원하고, 기존 자막과 회의록 서비스는 대화를 기록하는 데 강점이 있습니다. 보이스아이는 이 서비스를 대신하지 않습니다. 회의 중 놓친 구간을 바로 확인하고, 사용자가 작성한 의견을 확인 후 음성으로 전달하는 기능을 더해 회의 참여를 보완합니다. 본선에서는 자막 공백 표시가 실제 재확인에 도움이 되는지 기본 자막과 비교하겠습니다.

## 6쪽 — AI 활용 필요성 (2:10~2:50)

AI가 필요한 첫 번째 지점은 음성 인식입니다. 참석자의 자유 발화를 임시 자막과 확정 자막으로 바꿉니다. 두 번째는 음성 합성입니다. 사용자가 확인한 문장을 한국어 음성으로 재생합니다. 여기에 말소리는 있었지만 자막이 생성되지 않은 구간을 찾아 표시하는 기능을 개발하려 합니다. 익명 방향 추정은 얼굴 인식에 의존하지 않고 마이크 배열 입력을 우선 검토합니다.

## 7쪽 — 회의 중 사용 순서 (2:50~3:25)

사용 순서는 네 단계입니다. 먼저 참석자에게 음성 처리 방식을 안내하고 회의를 시작합니다. 사용자는 임시 자막과 확정 자막을 읽으며 잘못 인식된 내용이 있으면 다시 확인합니다. 의견이 있을 때는 문장을 입력하고 비공개 미리보기에서 내용을 확인합니다. 전송 버튼을 눌렀을 때만 음성이 재생되며, 필요하면 즉시 중지할 수 있습니다. 화면에 보이는 이미지는 실제 TTS 입력 화면입니다.

## 8쪽 — 노트북과 패널 연결안 (3:25~4:00)

초기 제품은 노트북을 중심으로 구성합니다. USB 마이크가 회의 음성을 입력하고, 키보드는 사용자의 발언 문장 작성에 사용합니다. 노트북이 음성 인식과 음성 합성, 자막과 오류 시각 기록을 처리합니다. 확인한 문장은 내장 또는 외장 스피커로 재생합니다. 투명 패널은 공유할 자막만 보여주는 확장안입니다. 영상 입력과 전원, 글자 가독성은 실제 장비를 확보한 뒤 시험하겠습니다.

## 9쪽 — 현재 구현과 본선 개발 범위 (4:00~4:35)

현재 작동을 확인한 범위는 문장 작성과 미리보기, 한국어 TTS 재생과 중지입니다. 브라우저 STT 코드는 구현돼 있지만 실제 마이크의 인식률과 지연은 아직 측정하지 않았습니다. 좌석과 겹침 표시는 대본과 고정 좌석을 사용하는 시연용입니다. 본선에서는 로컬 STT 후보인 faster-whisper를 비교하고, 자막 공백 확인과 익명 방향 추정을 조건별로 시험하겠습니다.

## 10쪽 — 인식 오류와 기록 처리 (4:35~5:10)

실시간 음성 인식에서는 정상 상황보다 오류 처리가 중요합니다. 인식을 끈 직후 다시 켰을 때 이전 인식기가 동작하거나 같은 확정 자막이 두 번 들어오는 문제를 먼저 막겠습니다. 무음이나 연결 끊김은 중단 사유와 다시 시작 버튼으로 안내합니다. 스피커에서 나온 합성 음성을 다시 받아 적는 문제도 차단하겠습니다. 저장과 외부 전송은 처리 경로와 삭제기한을 안내하고 동의를 받은 뒤 적용합니다.

## 11쪽 — 10월부터 12월 개발 일정 (5:10~5:35)

개발 기간은 10월부터 12월까지 12주입니다. 먼저 STT와 TTS, 공유 화면을 안정화합니다. 이후 참여자를 모집해 동의를 받고 시험 자료를 수집합니다. 중간에는 자막 공백과 오류 처리를 개발하고, 후반에는 사용성 평가와 조건부 방향 시험을 진행합니다. 마지막에는 시험 결과를 정리합니다. 전체 투입 계획은 240시간입니다.

## 12쪽 — 개발 자원과 예산 (5:35~6:00)

자체 예산안은 총 93만원입니다. 마이크와 주변기기 구매 또는 대여에 15만원, 낭독과 당사자 평가에 33만원을 배정했습니다. 외부 주석 검토 16만원, 전문가 자문 20만원, 교통과 소모품에 9만원을 계획했습니다. 현재는 견적과 섭외 전 가정이며, 투명 패널 제작과 유료 API 비용은 이번 예산에서 제외했습니다.

## 13쪽 — 참여자와 보상 계획 (6:00~6:25)

낭독과 모의 회의에는 성인 8명이 참여하는 것으로 계획했습니다. 청각장애인 사용성 평가는 4명을 모집해 문장 작성과 확인, 재생 중지 과업을 진행합니다. TTS 청취 평가는 낭독 참여자 중 청취 가능한 5명을 대상으로 합니다. 음성 정답은 대표자와 외부 검토자가 각각 표시한 뒤 합의합니다. 아직 모집 전이므로 실제 참여 인원과 수행 범위는 결과에 그대로 기록하겠습니다.

## 14쪽 — 활용 데이터셋 (6:25~7:00)

현재 보유한 회의 대본은 화면 전환 시험에만 사용합니다. 본선에서는 기관명과 숫자, 일반문장으로 구성한 한국어 문장 60개를 자체 작성하고, 성인 8명의 낭독과 모의 회의를 수집할 계획입니다. 15분 소규모 회의는 6회를 목표로 합니다. 개발 자료와 최종 시험 자료를 나누고, 참여자에게 녹음과 이용 목적을 안내합니다. 원음 접근을 제한하고 평가가 끝난 뒤 정한 기간 안에 삭제하겠습니다.

## 15쪽 — 평가 방법과 목표 (7:00~7:35)

평가는 정확도 하나만 보지 않습니다. STT는 문자 오류율과 발화가 끝난 뒤 최종 자막이 나오는 시간을 측정합니다. TTS는 자연스러움과 이름, 숫자 발음 오류를 확인합니다. 방향 추정은 확정한 건의 정확도와 전체 건의 일치율을 함께 공개합니다. 자막 공백 후보는 사람이 표시한 정답과 비교합니다. 회의 참여 평가는 내용 확인과 발언 성공, 재질문 부담을 살펴봅니다. 화면의 숫자는 모두 본선 목표값이며 실측 결과가 아닙니다.

## 16쪽 — 모두의 AI 실험실 활용계획 (7:35~8:05)

모두의 AI 실험실에서는 바이브코딩 지원을 활용해 STT 시작과 중지, 중복 자막 오류를 재현하고 수정하겠습니다. 제공되는 개발 도구와 클라우드 환경에서는 STT 엔진을 같은 조건으로 비교합니다. 사용한 프롬프트와 코드 변경분, 시험 결과를 함께 기록하겠습니다. 멘토링을 통해 음성 처리 방식과 접근성 평가 방법도 검토받겠습니다. 세부 도구와 사용량은 실제 제공 목록을 확인한 뒤 정하겠습니다.

## 17쪽 — 실제 사용할 프롬프트 (8:05~8:25)

프롬프트도 실제 오류와 시험조건을 구체적으로 적겠습니다. 예를 들어 인식을 중지한 뒤 이전 콜백이 늦게 도착하는 경우와 같은 자막을 다시 받는 경우를 재현하도록 요청합니다. 자막 공백을 찾을 때는 말소리와 자막 시각을 비교하되, 인식하지 못한 문장을 시스템이 추측해 채우지 못하게 합니다. 생성된 코드는 직접 읽고 다시 시험하겠습니다.

## 18쪽 — 기대효과와 초기 적용처 (8:25~8:55)

초기 적용처는 취업지원 소그룹 상담과 장애인 고용 사업장의 팀 회의입니다. 사용자가 질문과 의견을 전달했는지, 놓친 내용을 확인하는 시간이 줄었는지 평가하겠습니다. 기관 담당자 인터뷰를 통해 반복 사용 의향과 설치, 교육 지원의 필요성도 확인합니다. 가격은 먼저 정하지 않고, 실제 운영에 필요한 시간과 기능 사용 빈도를 확인한 뒤 검토하겠습니다.

## 19쪽 — 본선 결과물과 마무리 (8:55~9:30)

현재 보이스아이는 문장 작성과 미리보기, 전송, 한국어 음성 재생과 중지를 확인한 제한적 MVP입니다. 본선에서는 실제 마이크 인식률과 지연, 자막 공백 표시와 TTS 자연스러움을 조건별로 검증하겠습니다. 장치를 확보하면 얼굴 식별 없이 익명 발언 방향도 시험하겠습니다. 보이스아이가 청각장애인이 회의 내용을 읽는 데서 그치지 않고, 자신의 의견을 직접 전달하는 데 도움이 되는지 결과로 보여드리겠습니다. 감사합니다.

발표 목표 시간은 9분 30초이며, 남은 30초는 슬라이드 전환과 말이 늦어진 구간에 사용한다.
