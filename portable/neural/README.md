# VoiceEye 행사 준비 회의

Windows 기본 음성을 Supertonic 2 한국어 신경망 TTS로 교체했다. 발언자마다 F1·F2·M1·M2 음색을 사용한다. 사용자가 입력한 문장도 같은 모델이 기기 안에서 음성으로 만든다. 외부 음성 API나 키를 사용하지 않으며, 기본 음성으로 자동 전환하지 않는다.

## 발표장에서 실행

USB 배포본 전체를 복사한 뒤 `시연시작.bat`를 실행한다. 함께 들어 있는 Node 실행 파일이 로컬 파일을 브라우저에 제공한다. 설치, npm, Python이 필요하지 않다. 이 프로그램은 음성 인식을 처리하는 서버가 아니다. 음성 모델은 브라우저 안에서 실행된다.

Chrome 또는 Edge에서 모델 준비가 끝나면 회의 시작 버튼이 켜진다. 처음 여는 데 시간이 걸린다. 모델 파일을 찾으려면 로컬 HTTP가 필요하므로 HTML을 더블클릭하는 방식은 지원하지 않는다. 외부 인터넷 연결은 필요하지 않는다. 발표장 보안 정책이 USB 실행 파일을 차단하면 실행할 수 있으므로, 발표 전 해당 PC에서 확인해야 한다.

## 시연 순서

1. 회의 시작을 누른다. 금요일 고용 상담 행사의 준비물을 확인하는 첫 참석자 발언이 나온다.
2. 음성이 끝나면 Whisper base가 그 음성의 PCM을 인식한다. 인식 결과가 자막과 기록에 들어온다. 대본을 자막으로 대신 쓰지 않는다.
3. 다음 발언을 눌러 접수 담당과 장비 담당의 이야기를 듣는다. 자동 진행은 없다.
4. 손들기를 누른다. 다른 발언이 멈추고 “발언하겠습니다”라는 음성이 나온다. 중단된 참석자 발언은 완료 기록에 남지 않으며 다음에 다시 진행한다.
5. “물하고 종이컵도 필요합니다. 제가 챙기겠습니다.”라고 입력하고 보내기·음성을 누른다. 입력한 문장을 음성으로 전달한다. 재생이 끝나면 정확한 입력 문장이 기록과 추가 의견에 남는다.
6. 발언 마치기를 누르고 다음 발언을 누른다. 진행자가 의견을 확인한 뒤 원래 안건을 이어간다.

의견 입력 중, 미전송 초안이 있을 때, 음성 생성·재생·인식 중, 손을 든 동안에는 다음 참석자로 넘어갈 수 없다. 재생 중지는 미완료 발언을 성공으로 기록하지 않는다. Shift+Enter는 줄바꿈이며 한글 조합 중 Enter로 보내지 않는다.

## 구현 범위

- 회의실과 얼굴 이미지는 개념 이미지다. 실증 참여자 사진이 아니다.
- 참석자 발언은 합성한 행사 준비 시나리오다. 사람의 녹음이라고 설명하지 않는다.
- 발언자 표시는 시나리오의 좌석 정보다. 카메라·얼굴 식별·AI 화자 판정이 아니다.
- 자막은 발언 음성이 끝난 뒤 인식하는 구간 방식이다. 연속 실시간 마이크 STT를 검증한 제품이라고 설명하지 않는다.
- 한국어 음성 인식에는 오류와 지연이 있다. 인식 결과를 대본으로 몰래 바꾸지 않는다.
- 키보드 발언은 작성자가 이미 알고 있는 문장이므로 음성 인식에 보내지 않는다. 원문을 그대로 기록하고 TTS로 발음한다. 모델의 숫자·기호 발음까지 항상 원문과 동일하다고 보장하지 않는다.
- 대형 음성 모델을 포함해 이전 HTML 한 장보다 용량과 초기 메모리 사용량이 늘었다. 앱 표시와 회의 진행은 브라우저에서 이루어진다.
- 이번 발표판의 실제 마이크 입력은 포함하지 않았다. 기존 앱의 마이크 구현은 보존했다.

## 개발·검증

개발 PC: `npm ci`, `npm run setup:demo:neural`, `npm run build:demo:neural`, `npm run demo:neural`.
흐름 검사: `npm run test:demo:neural`. 배포 산출물: `portable/voiceeye-neural-demo`.

모델을 Git에 넣지 않는다. 다운로드 스크립트가 고정 revision에서 받아 파일별 SHA-256과 이용조건을 배포본에 보관한다. 모델 파일과 런타임은 USB 배포본에 모두 포함한다.
